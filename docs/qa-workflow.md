# Testing and visual QA

This document records how we verify the app as it grows. The product plan is in [Initial Implementation Plan](initial-implementation-plan.md).

## Every small change

1. For code changes, run the project-local native TypeScript type checker with `bun run typecheck` and the CSS token check with `bun run qa:check`. For documentation-only changes, check local links, referenced commands, and whitespace; browser captures and code tests are needed only when app behavior changes.
2. Exercise the behavior that changed. Add a lasting automated test when it protects an observable invariant or a bug that could recur.
3. For a UI change, capture the relevant state at four sizes and inspect the images for clipped controls, page-wide overflow, unreadable code, and obscured feedback actions.
4. Describe the behavior, checks, and any remaining device-specific uncertainty in the handoff to the maintainer.

Keep unit and integration tests focused on inputs and outputs. Prefer Git fixture repositories for status/diff behavior, bounded invalid-input cases for APIs, and browser interactions for comment, drawer, wrap, and copy flows. Avoid tests of private function call order, redundant getters, and snapshots of incidental DOM structure. Remove exploratory tests that would only create maintenance noise.

Keep the maintainer's running app available for review. Start fixture QA on a separate port with `--root "$PWD/qa/.artifacts"`; the inventory fixture is created by `bun run qa:fixture`, which refuses to overwrite an existing fixture. Client assets are shared under `dist/`, so rebuild the current client before the handoff and reload the review tab. Clean up QA processes you started without stopping the existing review service. Backend source changes need a restart of the relevant service; frontend-only edits need `bun run build`.

## Screenshot command

Start the local app, then run:

```sh
bun run qa:capture --url http://127.0.0.1:3000/ --label foundation
```

The command launches the installed Google Chrome through Playwright and writes `desktop.png`, `tablet-landscape.png`, `tablet-portrait.png`, `mobile.png`, and `manifest.json` to `qa/screenshots/foundation/`. Use a new, descriptive label for each reviewable milestone. The default is a viewport screenshot. Add `--full-page` when the entire continuous diff needs review, `--ready '.selector'` if a screen must finish loading, and `--click '.selector'` to open a control. Repeat `--click` for a sequence, such as the project switch then the install dialog. For a lazy diff, add `--after-click-ready '.diff-code'` so capture waits for its lines. `--help` lists options.

For the foundation picker, `bun run qa:foundation --url http://127.0.0.1:3000/ --folder <direct-child-name>` checks mobile folder selection and reload, then saves browser state under `qa/.artifacts/`. Browser state files omit per-tab `sessionStorage`; add `--active-path <folder-relative-path>` to capture the explicit Changes URL for a selected project at all four sizes. Combine it with `--storage-state` when the capture also needs saved drafts or preferences. To capture a particular Files or Search destination, pass its full `--url` with query parameters; direct links are the authoritative navigable state.

## Live change detection

Start the app with `--root "$PWD/qa/.artifacts"`, then run `bun run qa:live-changes http://127.0.0.1:3000/`. It creates and removes a temporary Git project. The script checks that a same-length edit to an already modified file raises the Update action without replacing the displayed diff, then confirms Update keeps an expanded card and draft comment. It checks the 320 px phone width, pausing in a hidden tab and checking immediately on return, serialized status requests, repeated-check error recovery, and manual Refresh. [Phone](../qa/screenshots/navigation-live-update-review/mobile.png), [tablet portrait](../qa/screenshots/navigation-live-update-review/tablet-portrait.png), [tablet landscape](../qa/screenshots/navigation-live-update-review/tablet-landscape.png), and [desktop](../qa/screenshots/navigation-live-update-review/desktop.png) show the pending action in the current shell. Inspect the action's reachability on real phone browsers as well as in emulation.

Run `bun run qa:voice http://127.0.0.1:3000/` against the inventory fixture to check transcript insertion at a saved caret, selected-range replacement, failure and Retry with the original clip, Cancel without upload, automatic Send at five minutes, and control access in a keyboard-sized viewport using a mocked recorder and endpoint. The [idle voice footer](../qa/screenshots/voice-comment-idle/mobile.png) and [recording footer](../qa/screenshots/voice-comment-recording/mobile.png) have four viewport captures. `qa:capture --fake-microphone` uses Chrome's synthetic microphone to capture recording controls. Browser emulation does not prove real microphone permission, audio capture, start/stop cues, or iOS/Android keyboard behavior. Test those on devices through the private HTTPS origin. A local endpoint smoke check can POST a non-sensitive WebM speech fixture to `/api/transcriptions`; it must return validated text through FFmpeg and Handy.

Run `bun run qa:tabs http://127.0.0.1:3000/` to check that two tabs can keep different projects across reload while sharing recents, and that the old shared selection migrates once. Run `bun run qa:pwa http://127.0.0.1:3000/` to check manifest/icon delivery, service-worker offline fallback, that API responses stay out of its cache, and draft backup export/import with invalid-file rejection. The current tailnet HTTPS deployment uses port 8443, leaving the machine domain's default HTTPS root free. The [live project view](../qa/screenshots/https-port-8443-review/mobile.png) has four-size captures from that address. The capture exits nonzero for page load failures or page-wide horizontal overflow. A horizontally scrolling **code pane** is allowed; the document itself should fit the viewport. Inspect the images rather than relying solely on the overflow check. Link useful screenshots in the human handoff. Generated test traces and temporary files belong in `qa/.artifacts/`; curated milestone screenshots remain under `qa/screenshots/`.

Use `--scroll-x-to-end '.diff-scroll'` to capture a code pane at its far-right edge. The [wrapped](../qa/screenshots/diff-marker-left-wrap/mobile.png) and [horizontal-scroll](../qa/screenshots/diff-marker-left-scroll/mobile.png) sets show compact rows, left-hand change markers, fixed gutters, and background coverage at all four sizes. The command uses desktop Chrome with emulated touch, viewport, and mobile settings for smaller screens. This does not reproduce mobile Safari or Android Chrome exactly. Use real devices for long press, double tap, keyboard/safe-area layout, clipboard, and voice recording before those features are called complete.

## Word-level diff detail

Use a Git fixture with several edited lines plus an inserted or deleted line. Expand its change card, then capture the [wrapped review](../qa/screenshots/word-detail-review/mobile.png) and [unwrapped, horizontally scrolled review](../qa/screenshots/word-detail-scroll/mobile.png) at all four standard sizes. The screenshots should keep syntax colors, source text, line-number gutters, and added/removed row colors intact while marking only changed spans on clear pairs. Check selection contrast and no page-wide overflow. `bun run qa:diff`, `bun run qa:selected-search`, and `bun run qa:feedback` cover compact rows, selected-code Search through decorated markup, and line comments/copy in mobile Chrome emulation. Verify native selection handles and comment tapping on real phones when reviewing the slice.

## Baseline matrix as features arrive

| Area | Behavior to verify |
| --- | --- |
| Host boundaries | Allowed root succeeds; traversal and symlink escapes fail; invalid API data is rejected. |
| Git layers | Staged, unstaged, and untracked changes stay separate, including two layers on one path; renames, deletion, binary files, and odd names are represented. |
| Review UI | Menu/list/content navigation works at phone, tablet, and desktop widths; files collapse; code wraps or scrolls inside its pane; no page-wide overflow. |
| Feedback | Old/new line anchors are clear; drafts survive reload; copy history records only successful copies; export includes path, layer, side, and line. |
| Search and files | Search result opens its file and line; older versions and unsupported previews fail safely. |
| Voice | Recording and cancellation, permission denial, insertion at the saved caret, upload limits, Handy errors, and temporary-file cleanup. |

Run checks for the feature being built; do not create an exhaustive suite before the corresponding behavior exists.

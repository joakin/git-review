# Working on git-review

Read the [documentation guide](docs/README.md), [project scope](docs/current/project.md),
[development conventions](docs/current/development.md), and
[working workflow](docs/current/workflow.md) before starting. Use the
[workspace map](docs/current/workspace.md) to find relevant package documentation. Read an active
draft when it applies to the task.

Keep work small and understandable. Inspect the implementation, explain material decisions, and
agree new feature scope before implementing. Follow the workflow for independent review, maintainer
feedback, staging, and explicit commit approval. Existing authorization for a task remains
sufficient within its agreed scope.

Repository access through the app remains read-only. Preserve path containment, validated
boundaries, resource ownership, and user feedback. Keep the app usable on phones, tablets, and
desktop, and keep the maintainer's running app available. Follow the
[testing guide](docs/current/testing.md) for appropriate checks and report what was actually
verified.
